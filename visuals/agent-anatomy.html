Anatomy of an agent

An agent is one API call with five slots filled in. That's it. Our app has four of them, and they all share the same skeleton; what changes is what goes in each slot. Pick an agent, then hover a slot to find it in the code. 


    

  


  

    

      
Same skeleton, different jobs

      
Every agent answers the same five questions. When one misbehaves, check the slots one at a time instead of rewriting the whole prompt.

    

    

      
Structured out = code can act on it

      
The selector and SQL agent return a Zod-checked object your code branches on. Only the aggregator returns free text, because only a human reads it.

    

    

      
The model remembers nothing

      
“List them” means nothing on its own. History is a slot you fill on every call, or the follow-up question fails.
